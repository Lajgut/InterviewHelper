## 🧠 Темы для подготовки (по этапам)

### 1. Алгоритмы / Live coding
Российский бигтех (особенно **Яндекс, Авито**) любит контесты. Уровень: LeetCode Medium, иногда Hard.
- **Обязательно:** массивы, строки, хеш-таблицы, два указателя,滑动窗口, графы (BFS/DFS), деревья, базовое DP.
- **Ресурсы:**
  - LeetCode (top 75–150), NeetCode
  - Яндекс.Контесты (алгоритмические задачи их уровня)
- **Цель:** решать Medium за 20–30 мин, проговаривая вслух.

### 2. Техническое интервью (Android Core)
Темы, которые спрашивают стабильно на senior/lead:

| Блок | Конкретно |
|------|-----------|
| **Kotlin** | Coroutines (структурированная конкурентность, cancellation, context), Flow vs StateFlow/SharedFlow, sealed classes, inline/reified, делегаты, мультиплатформа (KMP) — обзорно |
| **Архитектура** | MVVM / MVI / Clean Architecture, выбор,trade-offs, многомодульность, контракты между модулями |
| **Jetpack** | Compose (рекомпозиция, состояние, производительность), Navigation, Room, WorkManager, Hilt/Dagger, Paging 3 |
| **Производительность** | Профилирование (Profiler), память (leaks, LeakCanary), запуск приложения, UI-плавность (jank), R8/ProGuard |
| **Сеть** | OkHttp/Retrofit, перехватчики, пагинация, ретраи, обработка ошибок, HTTP-кэширование |
| **Фон** | WorkManager, Foreground Service, FCM, ограничения Doze/App Standby |
| **Тестирование** | JUnit, MockK/Mockito, Turbine для Flow, UI-тесты, тестируемость архитектуры |
| **CI/CD** | Git Flow/Trunk-based, feature flags, релизные поезда, Fastlane |
| **Глубокое** | Lifecycle компонентов, ViewModel, процесс/приложение, IPC, Binder — на уровне принципов |

### 3. System Design (мобильный) — ⭐ главный фильтр на senior+
Часто просят спроектировать **приложение целиком** или **часть системы** (библиотеку, фичу).

**Типичные задачи:**
- «Спроектируй ленту новостей / мессенджер / e-commerce приложение»
- «Спроектируй SDK/библиотеку аналитики»
- «Как организовать многомодульную архитектуру для приложения с 100+ разработчиков?»

**Что обсуждают:**
- Многомодульность (feature/data/core), стабильные API между модулями
- Архитектурные миграции (поэтапный переход, например MVP → MVI)
- Локальные данные: Room vs SQLDelight, кэш, офлайн-режим
- Сетевой слой: REST/gRPC, пагинация, ретраи
- DI-граф в масштабе (Dagger/Hilt/Koin)
- Push, фоновая синхронизация
- Производительность при росте (DEX, R8, startup)
- Design System, переиспользуемые компоненты, Compose vs View

**Фреймворк ответа** (держи его всегда):
1. **Уточнить требования** (functional + non-functional: SLA, оффлайн, масштаб)
2. **Capacity estimation** (DAU, RPS, объём данных)
3. **Высокоуровневая архитектура** (клиент ↔ API ↔ backend — грубо)
4. **Детализация клиентской части** (модули, слои, навигация, состояние)
5. **Тrade-offs и узкие места** (что жертвуешь и почему)

### 4. Менеджерское интервью (Team Lead компетенции) — ⭐ для лидов критично
Здесь проверяют **как ты управляешь**, а не кодишь. Формат — поведенческие вопросы (STAR).

**Темы и примеры вопросов:**
- **Управление командой:** «Расскажи про команду. Как росла? Как нанимал?»
- **Конфликты:** «Разработчик не согласен с архитектурным решением. Действия?»
- **Найм и увольнения:** «Как определяешь senior от middle на найме? Увольнял ли? Как?»
- **Мотивация / выгорание:** «Сильный разработчик выгорел и демотивирован. Что делаешь?»
- **Процессы:** «Как выстроен SDLC? Релизы, code review, planning, retro?»
- **Метрики:** «Какие метрики команды отслеживаешь? (DORA, скорость, качество)»
- **Взаимодействие со стейкхолдерами:** «Продакт хочет фичу, тех. долг горит. Приоритезация?»
- **Развитие людей:** «Как растишь middle → senior? 1-1, PDP?»

> 💡 **Готовь кейсы из реального опыта (в ВК):** 3–5 сильных историй на эти темы, в формате STAR (Situation–Task–Action–Result), с метриками.

### 5. Культурное интервью / Values
- Принципы работы, ценности конкретной компании (посмотри их careers-страницу).
- «Почему наша компания?», «Почему уходишь из ВК?» — подготовь честный позитивный ответ.

- [ ] **Неделя 1:** CV (RU), 5 кейсов STAR для менеджерского, начало LeetCode (1–2/день)
